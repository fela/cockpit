# Hub requirements

With a `[hub]` table in the setup, Cockpit shows and runs a CLIProxyAPI hub (SPEC UI-81, UI-84, UI-85 and UI-87). These four spec rows
are written for a machine without a hub; here they are with the hub's part, in the spec's columns, whose Evidence, Last
change and Comments are left empty as in the public spec.

| ID | Requirement | Origin | Strength | Status | Evidence | Last change | Comments |
| --- | --- | --- | --- | --- | --- | --- | --- |
| UI-37 | Cockpit shows when a Claude account's sign-in is about to expire, before it does, and when an account is signed out, so the user can sign in again in time; a signed-out account gets no new sessions. While Claude Code's settings send sessions to an API server (UI-81) the machine's sign-ins go unused, so no account counts as signed out and none warns (UI-84). | User | Should | Live |  |  |  |
| UI-40 | When a Claude account is signed out, Cockpit makes it plain at once, at the top of the page, and offers a sign-in from the page that takes as few steps as Claude allows: the user opens the sign-in, approves it, and Cockpit finishes it, with no terminal and no session in between. Once the account works again, every session whose turn ended with "Login expired" picks up the request it lost, the stopped ones and the sweeper included, and the sweeper runs a full sweep. A key that the model hub refuses ends a turn with the same error mark as a sign-out; Cockpit counts only a turn that says "Login expired" as a sign-out. | User (pain) | Should | Live |  |  |  |
| UI-77 | When a Codex account is signed out, Cockpit makes it plain at once, as a warning in Inbox (UI-52), and offers a sign-in from the page in as few steps as Codex allows, with no terminal and no session in between, as with Claude sign-in. A session that needs the user to sign a Codex account in, also as a precaution while it still works, sends the user to that sign-in instead of asking them to run a command. A Codex folder whose Codex runs through a model provider of its own config, such as the CLIProxyAPI hub (UI-81), holds no sign-in of its own, so it is not signed out and shows no warning. | User (pain) | Should | Live |  |  |  |
| UI-83 | A Claude account can have a weekly limit that counts one model's use alone (Fable), beside the weekly limit all models share. Where Cockpit shows a Claude account's weekly limit in detail, it shows both and names them. With a hub the usage display has Fable's limit as a family of its own (UI-84). On a machine without one its hover card (UI-12) gives a signed-in account two weeks, "All models" and the model's name, each with its own bar, share used and reset time. The display's spoken words give both figures, as in "personal 62% (Fable 38%)". The Usage page (SESSION-10) has a meter named for the model after the account's own. An account without such a limit keeps its single week. Without a hub the sidebar's lanes (UI-57) show the week all models share, and the choice of account for new sessions (SESSION-17) counts that week alone. | User | Should | Live |  |  |  |
