# Cockpit — living spec

Cockpit's requirements describe a personal work page for directing agent sessions.
Design decisions are explained in [REASONING.md](REASONING.md).

## How to read this

One row per requirement. Row IDs stay stable; gaps reflect removed requirements.

- **ID**: `AREA-n`, a stable identifier that is not reused.
- **Origin**: User, User (pain), or Agent; where the requirement originated.
- **Strength**: Must, Should, Could, Agent default, or Cut?; the requested priority.
- **Status**: Not done, In build, Shipped, Live, or Dropped. These describe implementation status, not a guarantee for every installation.
- **Evidence**: optional supporting facts. Personal conversations are omitted from this public copy.
- **Last change**: optional change note. Git records document revisions.
- **Comments**: optional implementation notes.

Describe product behaviour in each requirement. Keep implementation notes separate,
record revisions in git, and update status and reasoning when behaviour changes.

## Trade-offs

- A small queue limits context switching; the board keeps the rest of the work visible.
- Browser sign-in and agent tokens serve separate roles; only the user approves interactive requests.
- Live state helps ranking, while a focused step keeps its place as the user reads or replies.
